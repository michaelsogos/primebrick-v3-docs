The `primebrick-us-v3` repository contains the distributed microservices that
make up the Primebrick v3 backend. Each microservice is a self-contained
sub-folder with its own `src/`, `package.json`, `Dockerfile`, `db-meta/`, and
`terraform/` configuration.

## Tech stack

- **Runtime:** Bun (dev with `--hot` reload, prod with `bun dist/index.js`)
- **Language:** TypeScript® (strict mode)
- **HTTP:** Node.js® HTTP server via `@primebrick/sdk`'s `createHttpServer`
- **Messaging:** NATS™ (via `@primebrick/sdk`'s `NatsClient`)
- **Database:** PostgreSQL® (via `@primebrick/dal-pg`)
- **Package manager:** pnpm
- **Templates:** Handlebars (where applicable)

## Service catalog

| Service | Code | Port | Description |
|---------|------|------|-------------|
| [EmailSender](/dev/microservices/services/emailsender) | `emailsender` | 3003 | Email provider configuration, template rendering, and email dispatch via Brevo™ |
| [JobHandler](/dev/microservices/job-handler) | `job` | 3006 | Job scheduling, governance, and execution observability — NATS JetStream native scheduler, business `job_rules`, run history |

New microservices are added as new top-level sub-folders. Each must contain
a `package.json` with a `name` starting with `primebrick-` and a `src/index.ts`
entry point.

The Backend (BE) acts as the API gateway. The Frontend (FE) never calls
microservices directly — all HTTP traffic goes through the BE's
`/ws/:serviceCode/*` proxy. Inter-service async communication uses NATS™
subjects.

## Quick start

Each microservice is a self-contained sub-folder with its own `package.json`,
`src/`, `Dockerfile`, `db-meta/`, and `terraform/`. To run EmailSender
locally:

```bash
cd emailsender
pnpm install
pnpm run build
bun dist/index.js          # starts on port 3003 (from config table)
```

The microservice reads its NATS™ URL, HTTP port, and service code from the
`config_entries` table at startup via the SDK's `ConfigLoader` — not from env vars.
The only required env vars are `DATABASE_URL` and `DATABASE_SCHEMA` (the
service's owned PG schema — closed-set validated by `assertDbEnv()`).

To verify the service is running:

```bash
curl http://localhost:3003/health
# → { "ok": true, "service": "emailsender", "version": "...", "url": "..." }

curl http://localhost:3003/api/v1/openapi.json | head -20
# → { "openapi": "3.x.x", "info": { "title": "EmailSender", ... } }
```

From the Frontend, the same service is reached through the BE proxy:

```bash
curl http://localhost:3001/ws/emailsender/api/v1/entities/provider/list
# → { "rows": [...], "total": 0, "page": 1, "page_size": 20 }
```

To apply database migrations for a microservice:

```bash
cd emailsender && pnpm run db:migrate
```
