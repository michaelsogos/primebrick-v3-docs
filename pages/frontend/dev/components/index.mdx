Every component **unit** in `src/lib/components/` is listed here — a unit is a
component file or a directory of coordinated parts — grouped by origin.
**Custom** and **wrapped** components (we wrote or extended them) link to a
dedicated page on this site where one exists; **vendored primitives** used
unmodified link to their official registry docs.

Provenance is recorded in
`docs/dev-guide/_extracted/component-provenance.json` (hand-maintained). See
[UI stack](/frontend/dev/ui-stack) for how the registries layer.

> **Where new components live.** Every component/composable judged reusable
> lands in `@primebrick/ui` (`primebrick-v3-ui`) **at creation** — never in
> `src/lib/components`. Remote module bundles can only consume vendored
> packages, so anything FE-local is unreachable to remotes: "reusable" and
> "FE-local" are contradictory by definition. FE-local code is reserved for
> host-shell-only pieces; domain-specific components consumed only by one
> service's remote bundle stay in that service's `fe/`.
