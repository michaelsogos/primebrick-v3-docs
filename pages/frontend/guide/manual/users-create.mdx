Create a new user.

## Pages routes

- `/system/settings/users` — List, search and manage all users.
- `/system/settings/users/create` — Create a new user. *(this page)*
- `/system/settings/users/{uuid}` — View and edit an existing user.

Submitting the form calls `POST /api/v1/auth/users` and then opens the new user's detail page.

## How to create

1. Go to **Users** (`/system/settings/users`) and use the create action — the create page opens in a new browser tab.
2. Fill the form. Start from **Username** — required fields are marked below.
3. Click **Save**. You are redirected to the record's detail page.

## Fields

| Field | Required | Notes |
|-------|----------|-------|
| **IDP Username** | required | validated input — checked for availability in the selected organization while you type |
| **Password** | optional | checkbox — validated against the active password policy (live checklist); required unless *Send invitation* is enabled; max 64 |
| **Send invitation email** | optional | checkbox — When enabled, an invitation email will be sent to the user. They will set their own password via a secure welcome page. The password field above becomes optional — if left blank, a random placeholder is set in the identity provider and the user sets it on first access. |
| **Display Name** | required | text input |
| **Email** | required | text input — also used for the invitation email; max 320; must be a valid email; min 1 |
| **Application Roles** | optional | select — administrator roles show a System Administrator badge; min 1 |
| **Avatar Color** | optional | text input — shown when no avatar image is set; hex color |
| **Organization** | required | select — only organizations backed by a real identity-provider organization are listed; min 1 |
| **Enable** | optional | checkbox |
| **Admin** | optional | checkbox — The Identity Administrator flag allows the user to access the IDP system to make administrative-level changes, but does not grant administration rights to this application. To grant application administration access, set the application roles. |
| **Verified** | optional | checkbox — Indicates whether the identity verification process has been successfully completed. It may depend on a KYC process or other type of verification. |
| **Email Verified** | optional | checkbox — Indicates whether the email has been verified, typically via a link sent to the email inbox that is presumed to be readable only by the user whose profile we are configuring. |

## Actions

- **Save** — validates the form and creates the user (`POST /api/v1/auth/users`).
- **Cancel** — discards changes and returns to the previous page.
